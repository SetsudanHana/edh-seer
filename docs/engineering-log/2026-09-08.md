# State as of 2026-09-08

## An emblem is not a token, and it belongs to the player who gets it

Owner, on the Chandra, Fire of Kaladesh // Chandra, Roaring Flame commander page: *"−7 makes a
token this one is so wrong, emblem is not a token please check CRs"*, then, after the rules were
checked: *"you give those to a player, in this case to opponents, so you do not control those so
it is not your source of damage ... I would include emblems on graph same as we do with tokens
the deal damage should be part of emblem and chandra just creates it."*

The rules agree with the owner. CR 111.1: a token is a marker for a permanent. CR 114.1: an emblem
is a marker for an object with abilities and usually no other characteristics, put into the
command zone. CR 114.2: "[Player] gets an emblem with [ability]" means that player puts it there
and owns and controls it.

**Where the wrong reading was made.** The clause layer was right all along: `cardClauses` for
Chandra held verb `emblem`, object "an emblem with that ability", and the prompt itself says an
emblem is not `create`. The derive layer threw that away at one line,
`effect-kind.ts: emblem: "token-generation"`. Measured: 86 corpus cards carry an emblem clause,
and all 86 derived a `token-generation` ability, printed "makes a token", sat under the `makes
tokens` facet and voted Tokens in archetype detection. None formed an edge from it (the ability
has no emit); the damage was the sentence, the facet and the vote. The second half was older and
deliberate: `segment.ts` kept a granted clause on the card when the parent said "gets an emblem",
with a comment saying an emblem had no node to move it to. So Chandra's emblem trigger, "At the
beginning of your upkeep, this emblem deals 3 damage to you", sat on Chandra as her own ability
with control `you`.

**The design decision, and the fact that made it.** Scryfall treats an emblem as an object. Every
one has its own oracle id, layout `emblem`, and oracle text equal to the granted ability, and the
granting card's `allParts` names it as a `combo_piece` with an "Emblem — …" type line and a
printing id. That is the same exact join tokens were built on, so an emblem gets a node the way a
token does, with content from its own printed text rather than parsed out of the maker. Coverage
measured the same day: 140 corpus cards reference 87 distinct emblems; of the 86 cards with an
emblem clause, one (Karn, Living Legacy) has no Emblem part in Scryfall and keeps his clause on the
card, a claim on the wrong object over a deleted one. The alternative, a node synthesised from the
card's own quoted text, was rejected because it forks the structural rule and makes the Karn gap
the norm.

**What shipped (PR #268, one branch, fourteen tasks, each with its failing test first).**

- `ingest-tokens` runs a second search, `t:emblem`, because `is:token` returns no layout-`emblem`
  row. 138 printings merged by oracle id to 87 rows beside the 995 tokens. `normalize-tokens`
  accepts an Emblem `combo_piece` beside a token part, joined on printing id as before. The dry
  run asked for 393 rows at $0.98: the 87 emblems plus 306 token rows stale against the current
  vocabulary since an earlier bump. Owner's call to buy both. 392 persisted on the first run, one
  failed on a malformed model reply and persisted on the retry, 0 refused.
- Derive: `Characteristics.emblem?: true`, present only on an emblem row, beside `token: false`
  so "whenever a token enters" never matches one. `EFFECT_KINDS` gains `emblem`, and the grant's
  `subject.control` is the recipient the printed sentence names (`emblemRecipient`, one regex:
  "each opponent", "target opponent", "each player dealt damage" give `opp`; "target player" is
  yours, for the reason a plain "create" is in `createsForYou`). `grantedToOwnEmblem` is the
  token cue one object over, applied by `derive-corpus` only when the card has an Emblem part.
  `DERIVE_VERSION` 115, free.
- Matcher: `createdTokenRefs` keeps the one `combo_piece` that is not a card, flagged `emblem`;
  it never mediates. The node reuses `isToken` for plumbing, since every exclusion that flag
  drives applies to an emblem, and `characteristics.emblem` carries the rules meaning. No implied
  `cast`, `enters` or `dies`. An emblem an opponent gets is built from our seat by
  `flipPerspective`, every `you` and `opp` exchanged on subject, dealer and recipient, so
  Chandra's emblem deals damage to an opponent from a source the opponent controls. The maker
  edge is `creates:emblem`, keyed on the producer's `emblem` ability since a grant puts no event
  into the game, attributed to the face that prints "gets an emblem"; `createsForYou` refuses the
  ratings hop when an opponent gets it. Projection id space `emblem:`, flags on reasons and wire
  nodes. The tagger exports the vocabulary on a browser-safe subpath, `@edh-seer/tagger/emblem`,
  because the package root drags Node-only modules into the bundle (the bundle tests caught it).
- Web: a third dash pattern and the caption "emblem" on the board, "emblem" markers in the list,
  the drawer and the inspector, "N emblems they grant" in the list's count. And the loyalty cost
  the owner asked for the same hour: `LoyaltyCost` renders `+N`, `−N` and `0` as the printed
  shield with the number as real text, accessible name "minus 7 loyalty". Scryfall's symbol set has
  no loyalty badge (`+1.svg`, `-1.svg` both 404), so it is the site's own drawing.

existing `creates:` re-attribution banked it. Corpus after: 86 cards grant, 86 emblem rows, 74
with at least one ability (the rest are statics the derive layer says nothing about, which is

and no upkeep row; the emblem's row carries the upkeep damage. The all-Chandras deck through the
CLI now says *"When Chandra, Fire of Kaladesh is cast, Chandra, Dressed to Kill Emblem deals X
damage"*, the emblem's own trigger on the emblem's own node. Root suite 3,809 pass, 8 skipped,
0 fail. Static rebuilt to `v-497d2353456b`.

**Two things the same page still gets wrong, filed and not fixed.** The four-field event key has
no colour slot, so "whenever you cast a red spell" prints as "a spell being cast" while the matcher
joins on red; and the emit key drops `self`, so "untap Chandra" prints as a generic untap. Neither
forms a false edge on the live page (its partner events are non-combat damage, life loss and
entering); both are wording. The `self` half is small: the `when` column already carries the flag.
